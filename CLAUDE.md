# CLAUDE.md — working agreement for KOSPI-WATCHER

Guidance for any AI agent (or human) working in this repository. Read this
before changing code. It encodes safety invariants that **must not** be relaxed.

## What this is

KOSPI-WATCHER is a Korean-equity (KOSPI) market-analysis and **risk-controlled**
trading-research platform. Its product now **centers on market prediction + a
single-narrative daily brief** (like the sibling Fed-Watcher / KRW-Watcher
systems); the trading path is **secondary and paper-only**. The 21 analysis
agents are organised as a **hierarchical research-desk org** — 5 desks
(`DATA_INTEGRITY`, `MACRO`, `FLOW_TECH`, `FUNDAMENTAL`, `RISK`) plus a `CHIEF`
synthesizer, across 3 tiers (`VALIDATE → ANALYZE → SYNTHESIZE`),
`domain/agents/org.py`, ADR-016. A **deterministic** synthesizer
(`domain/prediction/synthesizer.py`, ADR-017) aggregates one full agent sweep
(`AgentService.run_all`) into a `MarketPrediction`: market regime (one of 9),
direction/confidence, **long / inverse / leveraged-inverse (곱버스) instrument
stances** over `069500`/`122630`/`114800`/`252670`, three scenarios, and a Korean
brief — **identical over mock-or-LLM findings** (it is deterministic over the
findings; `generated_by` records only whether they came from `"mock"` or
`"llm"`). The prediction now also carries a **visible deliberation** — each
agent's position → the desk lead's consensus-vs-dissent reconciliation (an
`agreement` ratio) → the Chief's aligned-vs-conflicted cross-desk reconciliation
into the house view (`Deliberation`/`DeskDeliberation`/`ChiefDeliberation` in
`domain/prediction/schemas.py`, built in the **same deterministic pass**, ADR-019)
— and is explicitly **labelled** with its `subject` ("코스피200 지수 방향 …") and
`horizon_label`. The daily brief is **news-aware**: it weaves in recent scraped
headlines (`PredictionService.generate(news_headlines=…)`, populated from
`repositories.recent_headlines`) and lists them as `news_refs`, without changing
the deterministic math.

**News scraping (keyless, dated, retention).** A keyless **Google News RSS**
provider (`infrastructure/news/`, parsed with **`defusedxml`**, never raises,
mock fallback) feeds `NewsService.scrape` (`newsfeed/service.py`), which dedups,
upserts, and **prunes anything older than `news_retention_days` (default 14)**
into the dated `news_items` table (grouped by KST `date_kst`). It feeds the
prediction; a worker `scrape_news` job (every 60 min) keeps it current (ADR-018).

**News daily brief — a separate artifact (NOT the forecast).** Distinct from the
**prediction report** (`MarketPrediction`, the *forecast*), the **news daily
brief** (`NewsBrief`, `domain/news_brief.py`, ADR-020) is a **news roundup** — a
themed digest *summarizing* the day's scraped headlines, with a one-line
`market_read` that ties the news to the latest prediction's regime/direction. It
is built **deterministically** by `build_news_brief` (`newsfeed/brief_builder.py`,
groups by topic, single-narrative summary), generated by
`NewsService.generate_daily_brief`, and **upserted one row per KST day** into the
`daily_briefs` table (PK `date_kst`). Do not conflate it with the prediction
report: the report is the forecast (`/prediction/latest`, `/brief`), the news
brief is the summary (`/news/brief`).

**Morning briefing → Telegram (08:00 Asia/Seoul, automatic).** The worker runs a
daily `morning_briefing` cron job at **08:00 Asia/Seoul** (`worker/scheduler.py`,
`CronTrigger` `hour=morning_briefing_hour` `minute=morning_briefing_minute`
`timezone="Asia/Seoul"`; defaults 8/0) that runs `run_morning_briefing`
(`briefing/service.py`): **scrape → generate+save the prediction report →
generate+save the news daily brief → send BOTH to Telegram**. Telegram delivery
(`infrastructure/telegram.py`, `send_telegram_message`) **never raises** and is
**skipped when `TELEGRAM_BOT_TOKEN`/`TELEGRAM_CHAT_ID` are unset** (token is a
`SecretStr`, never logged) — so without a token the data still refreshes, only the
push is skipped. **The worker process must be running for the 08:00 auto-delivery.**
`POST /api/v1/notify/morning` runs the same pipeline on demand (returns the
rendered messages + Telegram status), useful to preview/test without the cron or a
token (ADR-021).

New endpoints: `POST /api/v1/prediction/run`, `GET /api/v1/prediction/latest`,
`GET /api/v1/brief`, `GET /api/v1/agents/org`, `GET /api/v1/market/analysis`,
`GET /api/v1/analysis/instruments`, `GET /api/v1/backtest`,
`GET /api/v1/accuracy/track`, `GET /api/v1/stocks/recommendations`, `GET /api/v1/news`,
`GET /api/v1/news/dates`, `POST /api/v1/news/scrape`, `GET /api/v1/news/brief`,
`POST /api/v1/news/brief/run`, `POST /api/v1/notify/morning`; predictions persist
in `market_predictions` and the news daily brief in `daily_briefs`, and the daily
`morning_briefing` worker job (08:00 KST) keeps the latest (news-aware) prediction
+ brief current. Predictions/stances are **display-only** — they are NOT order
authority (the inverse/곱버스 ETFs are `tradable=false`, and any order still passes
the deny-by-default Risk Engine).

The web is a **modern multi-page UI** (Pretendard font, lucide icons, dark fintech
palette, Korea up=red/down=blue) with an 오늘 / 예측 / 정확도 / 시장 / 종목분석 /
종목추천 / 뉴스 / 에이전트 / 시스템 nav and a **disclaimer + ownership footer**
(`© 2026 안민규`); `/prediction` renders the deliberation thread +
Chief reconciliation, `/news` the dated headlines (ADR-019), `/market` the
**market-flow analysis** — live sector board + 외국인/기관/개인 flows (ADR-022) —
and `/analysis` the **per-instrument outlook** (ADR-023).

**Prediction tracking + auto-feedback (`/accuracy`, ADR-027).** The model is
deterministic, so it is *replayed* over history (`domain/prediction/
accuracy_track.py`) to build a **predicted-vs-actual time series** — two cumulative
curves, 실제(지수 매수보유) vs 모델(예측 방향 추종), with directional miss markers —
plus a **scorecard** (hit rate vs base rate, by-direction) and a bounded
**Calibration** (`direction_bias` + `confidence_scale`) derived from that scoring.
The calibration is fed back into `synthesize(...)` (and stored on
`MarketPrediction.calibration`), so scoring → calibration → next prediction →
re-scoring forms a self-improvement loop. `GET /api/v1/accuracy/track`; the
`/accuracy` page renders the SVG dual-line chart + scorecard + calibration card.
The same `trend_core` is scored and used, so the measured accuracy IS the live
prediction's accuracy.

**Individual stock recommendations (`/stocks`, ADR-026).** A deterministic
recommender (`domain/stocks/`) ranks a curated 30-name KOSPI/KOSDAQ universe into
**단기/중기/장기 Top picks**, combining real per-stock momentum with the house
view, the live sector board, BOK policy, structural themes, and news catalysts.
`GET /api/v1/stocks/recommendations`. Display-only 참고 자료 (면책); bold but reasoned.

**Price-trend anchor + accuracy backtest (ADR-025, recalibrated by ADR-029).**
The prediction anchors on the **real price trend** as its *primary* directional
driver. `trend_core` (`domain/prediction/trend_signal.py`) is a deterministic
past-only signal, recalibrated on 29y of ^KS11 with walk-forward selection +
held-out/KOSDAQ/bear-window gates (ADR-029): **bullish by default**; **bearish
only under strict confirmation** (price 3%+ below the 100-day SMA AND negative
60-day momentum AND SMA50<SMA200), and never a fresh bear call >10% below the
line (oversold rebound zone → weak default long). Warmup = 200 sessions
(`TREND_WARMUP`); NEUTRAL now only means insufficient history. It overrides the
FLOW_TECH `Breadth and Technical Agent` finding AND tilts the Chief score (above
the BOK tilt). The **same function** is run over 10 years of ^KS11 daily closes
(`infrastructure/marketdata/history.py`, keyless Yahoo; NOTE `range=max` is
broken on Yahoo for these indices) to measure **directional accuracy
out-of-sample**: `GET /api/v1/backtest` returns hit rate, `naive = max(base_up,
1-base_up)` base rate, and **skill** per horizon (D5/D20/D60), train/test split.
Measured gains vs the old symmetric rule: held-out-3y D5 hit 53.4→57.7%, D20
59.6→63.2%, coverage 86→100%, worst-regime composite −11.5→−3.4%p, with 2008/
2022 bear-window hits kept ≥0.5. Honest framing: skill vs the post-hoc
always-majority base rate stays slightly negative — the anchor's job is regime
alignment, not oracle-beating. Visible via `TrendSignalCard` + `BacktestCard` on
`/analysis` and `/prediction`.

**BOK monetary policy — a core macro driver (ADR-024).** The prediction now treats
Korean monetary policy (금통위·기준금리·총재 발언) as a first-class input. A
`MonetaryPolicySignal` (`domain/prediction/monetary_policy.py`) is built from an
**authoritative config override** (`MONETARY_POLICY_STANCE` = hawkish/neutral/
dovish + `MONETARY_POLICY_HIKES_2026`) or, in `auto` mode, a **keyword classifier
over BOK news headlines** (keyless; `source` = config/news/mock). It is injected
into the MACRO desk (overriding the Korea Macro + Rates agents' findings, NEUTRAL =
no-op) AND tilts the house direction at the Chief level (`_policy_tilt`, confidence-
weighted) so a confident hawkish read is *decisive* (hawkish → KOSPI bearish,
인버스/곱버스 favoured; 2 hikes → RISK_OFF, 3 → CRISIS). It is stored on
`MarketPrediction.monetary_policy`, woven into the brief, and shown via
`MonetaryPolicyCard` on `/prediction` and `/analysis`. Full 금통위 의사록/BOK 리포트
NLP is the upgrade path behind the same interface.

**Per-instrument analysis (`/analysis`, ADR-023).** The old `/trading` paper
screen was repurposed into a **종목 분석** surface (모의체결 UI 제거; the PAPER
backend + tests are kept). For each rung of the ladder (069500/122630/114800/
252670) it shows a **position verdict** — 매수(BUY)/중립(HOLD)/매도(SELL), reusing
the same `stance_for` the prediction uses — plus a **short/mid/long price outlook**
(signed expected return + low/base/high target range + Korean rationale). It is a
deterministic, display-only **model projection** (`domain/prediction/
instrument_outlook.py` over the latest house view + live prices; never order
authority): expected index drift from direction×confidence, amplified by the
instrument's exposure sign & leverage, **minus** the daily-rebalancing
volatility-decay drag (heaviest for 곱버스 over long horizons). `GET /api/v1/
analysis/instruments`.

**Market-flow analysis (`/market`, ADR-022).** A read-only "what moved KOSPI
today" surface: a **live, keyless sector board** (8 KODEX industry ETFs via Yahoo,
signed daily % vs `previousClose`; never-raises, per-sector mock fallback) plus
**investor flows** for 외국인/기관/개인. The flows have no keyless real-time KRX
feed, so they are **representative** (`flow_source="representative"`,
deterministic per KST day, ~zero-sum, sign aligned to the index move) and labelled
as such in the schema and UI — never presented as a real KRX print; a real
KRX/pykrx feed drops in behind the same `InvestorFlow` interface later. Display-only
(`GET /api/v1/market/analysis`); not order authority. The paper-trading allow-list
(`config/risk_limits.yml`) was expanded to the long/leveraged/inverse/곱버스 +
KOSDAQ ETF ladder (the PAPER backend endpoints + tests remain; the trading *UI* was
later replaced by the `/analysis` outlook screen, ADR-023).

It has two halves with a hard wall between them:

1. **Analysis** — 21 agents that *only* analyze. They emit `AgentFinding`s and
   have **no order-execution surface** (`AnalysisAgent` protocol in
   `src/kospi_watcher/domain/agents/base.py`). Agents can run on the deterministic
   **mock** runtime (default), a **real Anthropic LLM** (`AGENT_RUNTIME=llm` +
   `ANTHROPIC_API_KEY`, default model `claude-opus-4-8`, mock fallback on any
   error, ADR-015), or the **owner's Claude subscription** via the local Claude
   Code CLI (`AGENT_RUNTIME=claude_cli`, headless `claude -p` per agent call,
   token from `claude setup-token` at `~/.claude/oauth-token.secret`, default
   model `claude-sonnet-5`, same mock fallback; `infrastructure/claude_cli.py`,
   ADR-028) — **no runtime has order authority**.
2. **Execution** — a deterministic, **deny-by-default** Risk Engine is the *only*
   gate to an order, and `ExecutionGateway` is the *only* code that ever calls a
   broker. **PAPER (simulated) execution IS implemented and safe**: it moves no
   real money and contacts no real broker, runs only when `TRADING_MODE=PAPER`,
   and still passes the full Risk Engine + state machine + audit path
   (`PAPER_EXECUTION_IMPLEMENTED = True`; `PaperBrokerAdapter` / `TradingService`,
   ADR-014). **Live execution remains NOT implemented in this phase**
   (`LIVE_EXECUTION_IMPLEMENTED = False` in `src/kospi_watcher/config.py`); the
   gateway allows only the simulated MOCK/PAPER brokers and blocks any live broker.

Market prices (KOSPI/USDKRW/KOSPI200 ETFs) are **live via keyless Yahoo Finance**
with a labelled mock fallback; the provider never raises (ADR-013).

If you ever find yourself making an LLM/agent able to place an order, making a
single env var enough to send a *live* order, or letting PAPER fills look like
real ones, stop — that violates the design.

## Non-negotiable safety invariants

- **Deny-by-default risk.** Empty allow-lists mean *deny everything*. Every order
  must pass `RiskEngine.evaluate(...)`; only an `APPROVED` `RiskDecision` can
  build an `ApprovedOrder` (via `ApprovedOrder.from_decision`). See ADR-010.
- **No `float` for money or price — ever.** Use `Decimal`. Pydantic price fields
  use `DecimalNoFloat`, which raises on a raw `float`; the DB stores `Decimal` as
  TEXT (`DecimalString`) so precision is never lost. See ADR-008.
- **Time is timezone-aware and stored in UTC**; display is KST (Asia/Seoul).
  Naive datetimes are rejected at domain boundaries (`domain/time.py`). See ADR-009.
- **Arming live execution requires multiple independent gates** (mode +
  `live_trading_enabled` [+ `auto_execution_enabled` for unattended]). A single
  flag is never sufficient (`Settings.live_execution_armed` / `auto_execution_armed`).
  Even fully armed, **no live order can be produced** — the live path is not
  implemented (`LIVE_EXECUTION_IMPLEMENTED = False`).
- **PAPER is the only implemented execution mode, and it is simulated.** Orders
  execute only under `TRADING_MODE=PAPER`; `RESEARCH` refuses execution (HTTP 409).
  Paper fills are produced by `PaperBrokerAdapter.simulate_fill` — **no real
  broker, no real money** — and are labelled (`liquidity="PAPER"`,
  `PAPER-…` ids). Never present a simulated fill as a real one. See ADR-014.
- **Mandated defaults**: `TRADING_MODE=RESEARCH`, `LIVE_TRADING_ENABLED=false`,
  `AUTO_EXECUTION_ENABLED=false`. Do not change these defaults. (PAPER is opt-in
  per run/session via `TRADING_MODE=PAPER`.)
- **Secrets** are `SecretStr` and never logged or returned in any response schema
  (incl. `telegram_bot_token`; the Telegram sender reads it via `get_secret_value()`
  only and never logs it).
- **`config/risk_limits.yml` is safety-relevant.** Any change to allow-lists or
  limits must be recorded (ADR or change log) and reviewed.
- **`audit_logs` is append-only** (ADR-006). No update/delete path in app code.
- **Mock data is always labelled; live data is sourced honestly.** The mock agent
  runtime and the simulated brokers tag output (`[MOCK]`, `source="mock"`,
  `PAPER BROKER — SIMULATED FILLS…`) so it can never be mistaken for a real order.
  Live quotes carry `source="yahoo"`; fallback/offline quotes are `source="mock"`,
  `stale=True`. Don't blur the two.

## Layout

```
src/kospi_watcher/        # the package (src-layout, ADR-011)
  domain/                 # pure, no I/O: enums, time, money, agents, prediction, risk, execution
                          #   agents/llm_agent.py = real Anthropic agent (ADR-015)
                          #   agents/org.py = research-desk org chart (ADR-016)
                          #   prediction/ = synthesizer + regime + long/inverse ladder (ADR-017)
                          #   execution/{paper,position}.py = PAPER fills + PnL (ADR-014)
  infrastructure/         # db engine/session, redis client (fakeredis fallback)
                          #   marketdata/ = keyless Yahoo + mock provider (ADR-013)
                          #   news/ = keyless Google News RSS + mock provider (ADR-018)
                          #   telegram.py = Telegram Bot API sender, never-raises (ADR-021)
  db/                     # ORM models (12 tables), repositories, custom types, seed
  api/                    # FastAPI app, routes, request/response schemas
  agent_service/          # isolated analysis service (mock + llm) + PredictionService
  execution_gateway/      # isolated execution boundary (app + gateway)
  trading/                # TradingService — the PAPER execution orchestrator
  newsfeed/               # NewsService (scrape→dedup-upsert→prune) + brief_builder
                          #   = the news daily brief / news roundup (ADR-018, ADR-020)
  briefing/               # run_morning_briefing — scrape→predict→brief→Telegram (ADR-021)
  worker/                 # APScheduler jobs (morning_briefing 08:00 KST,
                          #   scrape_news hourly, heartbeat)
apps/                     # per-service entry points (api, agent-service,
                          # execution-gateway, worker) + web (Next.js, modern multi-page UI)
alembic/                  # five migrations (0001 initial, 0002 paper trading,
                          #   0003 market_predictions, 0004 news, 0005 daily_briefs),
                          #   SQLite + Postgres compatible
config/                   # risk_limits.yml, instruments.yml (+ agents/strategies)
docs/                     # ARCHITECTURE, DATA_DICTIONARY, AGENT_DESIGN, PRODUCT_SPEC,
                          # TRADING_SAFETY, THREAT_MODEL, RUNBOOK, ULTRAPLAN, adr/
tests/                    # unit + integration (pytest, httpx ASGI)
```

The dependency rule: **everything points inward at `domain`**; `domain` imports
nothing app-specific (no FastAPI, no SQLAlchemy session, no I/O).

## Local development (dockerless mode)

Windows PowerShell paths shown; the project targets Python **>=3.13** and is
developed/tested on 3.14.

```powershell
# 1. venv + install (SQLite + fakeredis; no Docker needed)
python -m venv .venv
.venv\Scripts\python -m pip install -e ".[dev]"

# 2. migrate the local SQLite DB
.venv\Scripts\python -m alembic upgrade head

# 3. run the API (http://localhost:8000, docs at /docs)
.venv\Scripts\python -m uvicorn main:app --app-dir apps/api --port 8000

# 4. the worker (optional)
.venv\Scripts\python apps/worker/main.py

# 5. the web app
cd apps/web; npm install; npm run dev   # http://localhost:3000
```

`DATABASE_URL` selects the backend: SQLite (`sqlite+aiosqlite://...`, default) for
local/CI, Postgres (`postgresql+asyncpg://...`) for prod. `REDIS_URL` empty →
in-memory fakeredis (reported honestly at `/health`). Copy `.env.example` →
`.env` to override; never commit `.env`.

### Enabling the new capabilities

```powershell
# Prediction report (the forecast — primary product surface) — no opt-in needed:
# POST /api/v1/prediction/run  → run all agents, synthesize, persist, return MarketPrediction
#                                (now incl. a visible deliberation + subject/horizon labels + news_refs).
# GET  /api/v1/prediction/latest  → latest stored prediction report (404 until first run).
# GET  /api/v1/brief              → the report's narrative brief (headline + narrative + long/inverse/곱버스 stances).
#                                   (NOTE: this is the prediction report — the NEWS daily brief is GET /api/v1/news/brief.)
# GET  /api/v1/agents/org         → the 5-desk + Chief research hierarchy (read-only).
# The worker's daily morning_briefing job (08:00 KST) keeps the latest prediction + news brief current.

# News scraping (keyless Google News RSS) feeds the prediction + news brief — no opt-in needed:
# POST /api/v1/news/scrape  → fetch configured topics, dedup-upsert, prune past retention.
# GET  /api/v1/news[?date=YYYY-MM-DD]  → dated headlines;  GET /api/v1/news/dates → dates + counts.
# The worker's scrape_news job (every 60 min) keeps it current. Force offline mock if needed:
$env:NEWS_PROVIDER = "mock"   # default "google" (keyless); NEWS_RETENTION_DAYS defaults to 14.

# News daily brief — a NEWS ROUNDUP, separate from the prediction report (forecast):
# GET  /api/v1/news/brief       → latest news daily brief (404 until first run).
# POST /api/v1/news/brief/run   → build+persist today's brief (one row per KST day, upsert).

# Morning briefing → Telegram (08:00 Asia/Seoul, AUTOMATIC when the worker runs):
# The worker's morning_briefing cron (08:00 KST) does scrape→predict→news-brief→Telegram,
# sending BOTH the prediction report and the news brief. Set the secrets to enable delivery:
$env:TELEGRAM_BOT_TOKEN = "123456:ABC..."   # SecretStr; unset ⇒ delivery skipped (never raises)
$env:TELEGRAM_CHAT_ID   = "123456789"       # both required (Settings.telegram_enabled)
# Override the time via MORNING_BRIEFING_HOUR / MORNING_BRIEFING_MINUTE (default 8 / 0).
# Run the worker (REQUIRED for the 08:00 auto-delivery):
.venv\Scripts\python apps/worker/main.py
# Or trigger the same pipeline on demand (no cron / token needed to preview the messages):
# POST /api/v1/notify/morning  → runs scrape→predict→brief→Telegram, returns rendered msgs + status.

# Live market data is ON by default (keyless Yahoo). Force offline mock if needed:
$env:MARKET_DATA_PROVIDER = "mock"
# GET /api/v1/market/quotes  → live (or mock) quotes for KOSPI/USDKRW/ETFs.

# PAPER (simulated) execution — opt in per session; live stays gated/unimplemented:
$env:TRADING_MODE = "PAPER"           # RESEARCH (default) refuses execution (HTTP 409)
# POST /api/v1/orders  → risk-gated simulated fill; GET /api/v1/positions, /api/v1/account.

# Real LLM agents (Anthropic). Needs the [llm] extra + a key; falls back to mock:
.venv\Scripts\python -m pip install -e ".[llm]"
$env:AGENT_RUNTIME = "llm"; $env:ANTHROPIC_API_KEY = "sk-ant-..."
# AGENT_MODEL defaults to claude-opus-4-8; set claude-sonnet-4-6 for a cheaper tier.
# POST /api/v1/agents/run  → configured runtime; /system/status reports agent_runtime.

# Real LLM agents on the OWNER'S CLAUDE SUBSCRIPTION (no API credits; ADR-028).
# One-time: `claude setup-token` → token stored at ~/.claude/oauth-token.secret
# (or CLAUDE_CODE_OAUTH_TOKEN). Then:
$env:AGENT_RUNTIME = "claude_cli"     # AGENT_CLI_MODEL defaults to claude-sonnet-5
# Falls back to mock per agent if the CLI/token is missing or a call fails.

# Site-triggered refresh (the public web's 자동/수동 업데이트; ADR-028):
# POST /api/v1/sync/run     → background scrape→predict→brief; single-flight +
#                             SYNC_COOLDOWN_MINUTES (default 10) guard the public button.
# GET  /api/v1/sync/status  → progress/stage, runtime+model, staleness, cooldown.
# The web home auto-fires one refresh when opened on data older than SYNC_STALE_HOURS
# (default 6); no Telegram from web syncs unless SYNC_NOTIFY_TELEGRAM=true.
```

Do **not** persist `TRADING_MODE`/`AGENT_RUNTIME` overrides into committed defaults
or `.env.example` — the mandated defaults (RESEARCH / mock-capable) stay put.

## Conventions

- Pydantic v2 everywhere; `model_config = ConfigDict(extra="forbid")` on domain
  models. Enums are `StrEnum` — persist the string *value*, never the position.
- Module names avoid shadowing stdlib/3rd-party (`logging_config.py`,
  `infrastructure/redis_client.py`).
- Tests: `pytest` with `asyncio_mode=auto`; integration tests use an httpx
  `ASGITransport` against a throwaway SQLite DB (see `tests/conftest.py`).
- New LLM-backed agents should target the latest Claude models (the `LLMAgent`
  default is `claude-opus-4-8`), use the forced `emit_finding` tool for structured
  output, let the server fill trusted fields, keep the `AgentFinding` schema (bump
  `AGENT_FINDING_SCHEMA_VERSION` on breaking changes), and must remain
  analysis-only (no order authority). See ADR-015 / AGENT_DESIGN §6.
