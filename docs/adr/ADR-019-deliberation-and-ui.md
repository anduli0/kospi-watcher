# ADR-019: 에이전트 논의 가시화(데스크 토의→수석 조율) + 모던 다중 페이지 UI(Pretendard·배너 내비) + 면책 고지·소유권

## Status

Accepted (2026-06-17)

## Context

ADR-016·ADR-017로 21개 에이전트가 5데스크+Chief 계층에서 **결정론적으로** 하우스 예측으로 종합되지만, 사용자에게는 최종 수치(방향·확신·국면·스탠스)만 보였다. 종합 과정 — 어떤 데스크가 어떤 합의/이견을 거쳤고, 수석이 데스크 간 갈등을 어떻게 조율했는지 — 은 코드 안에만 있었다. 제품이 "분석 리서치 회사"를 표방하고 브리핑이 "왜 이 방향인가"를 한 서사로 설명하려면(사용자 선호: 한 이야기로 엮기), **그 논의 과정 자체가 가시화**되어야 한다. 동시에, 초기 웹은 Phase 1 골격(5페이지, 기본 스타일)이라 예측·뉴스·논의 같은 새 산출물을 담기에 정보구조·미감이 부족했고, 일반에 공개되는 화면으로서 **면책 고지(disclaimer)**와 **소유권(ownership)** 표기가 없었다.

요구사항: (a) 예측을 만든 **논의 과정**(각 에이전트 입장 → 데스크 리드의 합의·이견 조율 → 수석의 데스크 간 조율)을 데이터로 기록하고 화면에 보여준다. (b) 이는 **추가 LLM 호출 없이** 기존 결정론 종합(ADR-017)과 **같은 패스**에서 산출되어 재현 가능해야 한다(무권한·결정론 불변식 유지, ADR-001). (c) 웹을 **모던 다중 페이지 UI**로 재설계해 예측·뉴스·논의·트레이딩을 일관된 내비게이션으로 담는다. (d) 한국 증시 관습(**상승=빨강, 하락=파랑**)을 따른다. (e) 모든 화면에 **면책 고지**와 **소유권** 고지를 둔다.

## Decision

종합기(`domain/prediction/synthesizer.py`)가 결정론 종합과 같은 패스에서 **논의 기록(`Deliberation`)**을 만들어 `MarketPrediction`에 싣고, 웹(`apps/web`)을 Pretendard 기반 모던 다중 페이지 UI로 재설계하며 면책·소유권 푸터를 전 페이지에 둔다.

1. **논의 계약(`domain/prediction/schemas.py`).** `AgentPosition`(`agent`, `is_lead`, `direction`, `confidence`, `note`), `DeskDeliberation`(`desk`, `title`, `consensus`, `agreement`, `positions`, `dissent`, `lead_note`), `ChiefDeliberation`(`overall`, `aligned_desks`, `conflicted_desks`, `note`), 이를 묶는 `Deliberation`(`desks`, `chief`)을 정의한다. `MarketPrediction`에 `deliberation: Deliberation | None`을 추가한다.

2. **데스크 토의→리드 조율(`_desk_deliberation`).** 응답한 각 멤버를 `AgentPosition`으로 기록하고(데스크 **리드**는 `is_lead` 표시), 데스크 `consensus`는 ADR-017의 데스크 `lean`(임팩트×확신·리드 ×1.5 가중 점수의 ±0.15 밴드 lean)으로 둔다. **합의도 `agreement` = 합의 인원 / 응답 인원**(응답 0이면 0.0). consensus와 **정반대 방향**(강세↔약세; 중립은 이견으로 세지 않음)인 멤버를 `dissent`로 모으고, 리드 화법의 `lead_note`("<lead>(리드): N/M건 <방향> 합의, 이견 K건은 리드가 가중·조율")로 **이견이 리드 가중으로 어떻게 단일 데스크 뷰에 조율되었는지**를 드러낸다.

3. **데스크 간 수석 조율(`_chief_deliberation`).** **4개 방향성 데스크**(`DIRECTIONAL_DESKS`)를 하우스 `direction`(ADR-017의 데스크 가중 합산 점수) 기준으로 **지지 데스크(`aligned_desks`, lean이 하우스와 일치)**와 **이견 데스크(`conflicted_desks`, 정반대 lean)**로 나누고, 지지 데스크의 **가중 합**을 더해 "몇 개 데스크가 어느 가중으로 지지, 몇 개는 이견 → 하우스 방향 확정(확신 X%)"을 `note`에 기록한다. 데스크가 갈려 전체 점수가 ±0.12 밴드 안이면 하우스 뷰는 `NEUTRAL`임을 명시한다. 수석은 ADR-016처럼 **합성만 하고 투표하지 않는다**(weight 0).

4. **같은 결정론 패스.** 논의는 추가 에이전트 실행·LLM 호출 없이 종합과 동일한 finding 위 결정론 패스에서 만들어지므로 **재현 가능**하고 mock·LLM finding에서 동일하다 — 기존 데스크→수석 수치를 **읽히게(legible)** 만들 뿐이다.

5. **모던 다중 페이지 UI(`apps/web`).** 루트 레이아웃(`app/layout.tsx`)이 **Pretendard** 가변 폰트(CDN)를 로드하고 모든 페이지를 sticky `NavBar`·`SiteFooter`(`components/nav.tsx`)로 감싼다. 팔레트는 다크 핀테크 테마(CSS 변수, `app/globals.css` → `tailwind.config.ts`)이며 **한국 관습 상승=빨강(`--up`)·하락=파랑(`--down`)**을 따른다. 내비: `오늘`(`/`) · `예측`(`/prediction`) · `뉴스`(`/news`) · `에이전트`(`/agents`) · `트레이딩`(`/trading`) · `시스템`(`/system`)(추가로 `/dashboard`·`/risk`). **`오늘`**은 간결한 데일리 브리프 랜딩(라이브 시세 스트립, 방향·확신·국면 + 예측 대상/기간 라벨의 히어로, 서사 브리프와 반영 뉴스, 롱/인버스/곱버스 스탠스 사다리)과 **배너 버튼 내비**로 상세 페이지를 연다. **`예측`**은 티어별 조직도와 함께 **논의 스레드**(데스크별 카드 — 에이전트 입장·이견 강조)와 **수석 종합 카드**(지지/이견 데스크), **예측 대상/기간** 라벨, 종목 스탠스·시나리오·브리프를 보여준다. **`뉴스`**는 일자별 그룹·일자 필터·스크랩 버튼·보존 안내를 보여준다(ADR-018).

6. **면책 고지·소유권 푸터.** `SiteFooter`가 전 페이지 하단에 **면책 고지**(정보 제공 목적·투자 자문/매매 권유 아님; 예측·국면·스탠스는 알고리즘/에이전트 생성 참고 자료로 정확성·완전성 미보증; 인버스·레버리지(곱버스)의 일일 리밸런싱 변동성 손실(데케이)·원금 손실 위험; 시세=Yahoo·뉴스=Google News·분석=mock/LLM 명시; 실거래·실계좌 미제공, 트레이딩은 페이퍼만)와 **소유권**(`© 2026 YellowScale · 안민규(Minkyu An). All rights reserved.`)을 표기한다.

7. **무권한·라벨링 불변식 유지.** 논의 가시화는 분석 계층 내부 구조를 드러낼 뿐 어떤 에이전트·데스크·수석도 주문 권한을 얻지 않는다(ADR-001). 예측은 `subject`("코스피200 지수 방향 …")·`horizon_label`로 **무엇을·어느 기간**에 대한 것인지 라벨되고 화면에 함께 표기된다(ADR-017). mock/페이퍼 라벨, 면책 고지로 실데이터·실거래 오인을 막는다.

## Consequences

- 사용자가 **"왜 이 방향인가"**를 데스크 토의→수석 조율의 한 흐름으로 본다 — 예측이 블랙박스가 아니라 설명 가능한 논의의 산물이 되어 신뢰·이해가 높아진다(ADR-016 데스크 구조 활용).
- 논의가 **기존 결정론 종합과 같은 패스**라 추가 비용·비결정성이 없다. mock·LLM finding에서 동일하게 재현되며, 데스크 합의도·이견·지지/이견 데스크가 데이터로 남아 감사 가능하다.
- 웹이 **모던 다중 페이지 UI**가 되어 예측·뉴스·논의·트레이딩을 일관된 내비로 담고, `오늘` 랜딩이 데일리 브리프 중심으로 정리된다. 한국 관습(상승=빨강·하락=파랑)을 따라 직관적이다.
- 전 페이지 **면책 고지·소유권** 표기로 공개 화면으로서의 법적·윤리적 고지를 갖추고, 인버스·레버리지 리스크와 "참고 자료" 성격을 분명히 한다.
- 새 스키마 필드(`deliberation` 등)는 `MarketPrediction`에 더해지며 `PREDICTION_SCHEMA_VERSION`은 호환 범위에서 유지된다(추가 필드는 옵셔널). 논의 임계(데스크 ±0.15, 전체 ±0.12)는 ADR-017의 종합 임계를 그대로 따른다.
- **무권한 불변식 유지.** 가시화·UI는 표시 계층일 뿐, 주문 게이트는 여전히 deterministic Risk Engine뿐이고 예측·스탠스는 표시용이다(ADR-001, ADR-010, ADR-017).

## Alternatives Considered

- **최종 수치만 보여주고 논의는 숨김(rejected).** 구현은 쉽지만 예측이 블랙박스로 남아 "왜 이 방향인가"를 설명하지 못하고 제품의 "리서치 회사" 서사가 약해진다. 같은 결정론 패스에서 논의를 기록·노출한다.
- **논의를 LLM에게 작문시킴(rejected).** 데스크/수석 토의를 LLM으로 생성하면 비결정·비재현이고 감사가 어려우며, 결정론 종합(ADR-017)과 어긋난다. 논의는 기존 수치 종합을 규칙적으로 서술한 결정론 산출물로 둔다.
- **별도 분석 패스로 논의를 재계산(rejected).** 종합과 별개로 한 번 더 돌리면 비용이 늘고 두 산출물이 어긋날 수 있다. 종합과 **같은 패스**에서 만들어 일관성을 보장한다.
- **기존 Phase 1 UI 유지(rejected).** 새 산출물(예측 논의·뉴스)을 담기엔 정보구조·미감이 부족하고 공개 고지가 없다. Pretendard 기반 다중 페이지로 재설계하고 면책·소유권 푸터를 둔다.
- **미국식 색 관습(상승=초록·하락=빨강)(rejected).** 한국 사용자 대상 제품이므로 혼동을 막기 위해 **상승=빨강·하락=파랑** 한국 관습을 따른다.
- **면책 고지를 약관 페이지로 분리(considered, not chosen).** 별도 페이지로 빼면 대부분 사용자가 보지 못한다. 전 페이지 푸터에 상시 노출해 고지 효과를 높인다.
